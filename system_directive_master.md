# 🎨 Section I: Master Executive Typography & Formatting Rules

To ensure every document generated by NotebookLM or Goings OS engines reads like a human executive wrote it for publication, all outputs must strictly adhere to these typographic constraints:

* No ASCII or Code Dividers: Never use raw equal sign lines (===), repeated hyphens (---), asterisks (***), or horizontal rule lines. Visual separation is created naturally through bold headings, subtle callout boxes, and natural paragraph spacing.
* No Em-Dashes: Em-dashes are strictly prohibited under all circumstances. Use colons, commas, periods, or parentheses for clause structure.
* No Raw Code Blocks on Prose: Do not wrap standard text, SOPs, or memos in code block wrappers. Reserve code blocks exclusively for executable software scripts or code snippets.
* Emoji Anchors: Use clean, professional emojis (such as 📘, 🎯, 🛠️, ⚙️, 📋, ✅, 💡) strictly as visual anchors at the start of major section headings.
* Callout Blocks: Use indented blockquotes or subtle callout formatting for prompts, warnings, and legal notices to maintain a high-end, published layout.

# 📘 Section III: The 6-Part Foolproof Pedagogical Standard

Every student-facing document, lesson worksheet, and SOP must follow this exact 6-part structure:

1. Purpose and Goal: Plain English explanation of the operational outcome, completely free of technical jargon.
2. Tools Needed: Itemized list of required software, accounts, or links.
3. Step-by-Step Execution: Sequential, numbered, click-by-click instructions.
4. Copy and Paste Asset: Ready-to-use prompt schemas or template blocks.
5. Definition of Done: Clear, verifiable criteria confirming successful completion.
6. Troubleshooting: Practical fixes for the top two common user errors.
